# Simulation library: API notes and design decisions (T3 + T4)

Engine-agnostic C# 9 (asmdef `BoingUpSkyTower.Simulation`, no engine references). Fixed-point `Fx` (Q16.16) and integers only, seeded `Rng`. No `float`, `System.Math`, LINQ-heavy code or JSON in this folder. `Sim.Step` never allocates (checked by a test). The sources are compiled by `Tests/Simulation/*.csproj` straight from `Assets/`, so anything that builds there builds in Unity 6.

## How Unity code builds a level and runs it

```csharp
SimConfig cfg = new SimConfig();                       // later: fill from Remote Config
LevelSpec spec = new LevelSpec {                       // map the level JSON to this (see Tests/Simulation/ContentLoader.cs)
    Seed = json.seed,
    Difficulty = LevelGenerator.EffectiveDifficulty(baseD, regionOffset),   // d_eff, as Fx
    LevelIndex = json.index,                           // 1..15
    Class = 0..4,                                      // simple, medium, hard, complex, highly complex
    Goal = new GoalSpec { Type = GoalTypes.FromId(json.goal.type), Value = .., Count = .., TimeSec = .. },
    Stars = ...,                                       // StarSpec.Kind 0 clear, 1 coins, 2 noRevive, 3 time
    Signature = SignatureKinds.FromModuleId(region.rules.signatureModule),
    Ramp = overrides.ramp, FixedChunks = overrides.fixedChunks };
LevelData data = LevelBuilder.Build(cfg, spec);        // deterministic, same on every device
Sim sim = new Sim(cfg, data, spec);                    // difficulty and ramp come from the spec
SimState s = sim.NewState();
sim.Step(ref s, SimInput.Right | SimInput.Jump);       // once per 1/60 s; Jump is an edge flag
if (GoalEvaluator.IsComplete(spec, s)) {               // check after every Step
    int stars = StarEvaluator.Stars(spec, s, revivesUsed: s.RevivesUsed, ticks: s.Tick);
}
if (s.Dead) sim.Revive(ref s);                         // after the caller's revive UI/payment succeeded
```

Rendering reads `data.Platforms` (use `sim.PlatformX(id, tick)` for moving platforms), `data.Hazards` (use `sim.HazardPosition(id, tick, out x, out y)`), `data.Pickups` with `s.PickupTaken[id]` for the collected flag, and the counters on `SimState` (`Coins`, `Gems`, `HiddenGems`, `Hits`, `Invuln`, `Combo`, `BestCombo`, `WallBounces`, `RevivesUsed`).
`SimState.Clone()` deep-copies the two arrays (`CrumbleTick`, `PickupTaken`); copy states with it, never with plain assignment, when branching.

Endless mode is unchanged: `new Sim(cfg, LevelGenerator.Generate(cfg, endlessParams), d, endless: true)`; the per-landing coin rule is off there (doc 08 D3).

## Rules and decisions (all values are SimConfig fields unless noted)

**Doc sync 2026-10-20.** Several paragraphs below were written before the owner's device-test decisions and keep their history. Where they conflict, doc 08 (sections "Scroll model", "Jump numbers", "Pickups and feedback", "Economy v2 details") and the notes marked "Update" win: (1) scroll: the screen scrolls after the first jump, base `ScrollBasePercent` 120, steps `GameSettings.DifficultyStepPercent` {20, 40, 60, 80, 100} percent per 5 s, cap `ScrollStepCapPercent` 400 (set in `GameSession`; the `SimConfig` defaults 4 and 50 are the unit-test baseline), the bottom edge kills, no hazard from below; (2) economy v2: no coin pickups and no `CollectCoins` goal, 3 collectible stars per level, gem rarity tiers `GemRarityPercent` {70, 22, 7, 1} for 1/2/5/10 gems, coins paid at the end by `Rewards`; (3) no time star and no timed goal; Speedrun levels are reach-floor goals; (4) the "Jump height" and "Star pickups" paragraphs are current.

**Rows.** `RowsFor()`: an explicit `Rows` wins; ReachFloor, Speedrun and BossChase use `Goal.Value`; every other goal uses 60; never below 30. `TargetRow()` is the row the goal checks (`Goal.Value` for row goals, the top row for the others).

**Jump height (owner decisions 2026-10-20, playtest lists 6 and 7).** A single standing jump (no horizontal speed) must reach the next platform, but not cross two. `JumpBase` 19 u/s and `JumpSpeedFactor` 0.58 (history: 14 / 0.85 until the morning, 21 / 0.85 for a few hours, then these). Standing peak 4.51 u = 1.30 median row gaps (median normal gap 3.48 u, mean 3.47, p90 4.2 over regions 1 to 5); full-speed launch 24.2 u/s peaks at 7.33 u = 2.10 median gaps; half speed 5.84 u. The generator caps every vertical row gap at `NormalGapMax` 4.2 u (builder, generator, chunk rows and the combo ladder start), 0.3 u under the standing peak, so the largest normal gap is now about 4.2 u (was 5.19). Layouts are sized from the layout reference jump `LayoutJumpBase` 14 u/s and `LayoutJumpSpeedFactor` 0.85 (`LayoutMaxJumpHeight()` 5.86 u, `LayoutMaxReachDx`): its full-speed launch (21.65 u/s) is below the real one (24.2), so every generated dx is covered (test `LayoutReachNeverExceedsTheRealFullSpeedReach`). Narrow-platform caps, sticky (`StickyNextGapMax` 1.8 since QA region 4: the sticky standing peak is 2.10 u in the Sim, not 2.2, so 2.2 was out of reach of a standing jump; `Region4Tests`), bounce and combo ladder caps are unchanged. `MaxJumpHeight()` and `MaxReachDx()` are the real physics. Tests: `StandingJumpReachesTheLargestNormalRowGapWithMargin`, `JumpPeaksAreAboutOneAndTwoMedianGaps` (1.2 to 1.4 and 1.9 to 2.3). Hand-built test worlds that encoded the old jump were rescaled (heights 1.8 / 3.6 / 5.4 / 7.2).

**Star pickups (2026-10-20, playtest list 6: "had to cross the star twice").** Root cause: `RunView.PickupVisualY` lifted any star or gem that overlapped a platform slab zone up onto that platform, so the star was drawn up to about 1.5 u away from where the Sim collects it (stars sit 1.2 or 1.8 u above their row platform, which is inside the slab zone of the next row). The player touched the drawn star and nothing happened until the second pass through the real spot. Fixes: the builder now moves stars and gems up out of every platform slab zone (`IsPickupClearOfPlatforms`), the view draws every pickup exactly at its Sim position, and `Sim.CollectPickups` tests the path of the player centre between the previous and current tick against the pickup circle (integer segment distance), so a fast pass cannot skip a pickup between ticks. Radius is unchanged (`StarRadius` 1.0).

**Signature template (doc 08 section 6).** Level 1 and 2: no signature platforms, no hazards, no chunks. Level 3: share `SignatureIntroPercent` (10). Level 4 and up: `SignatureBasePercent` (15) growing linearly with d to `SignatureMaxPercent` (40). Region 1 = `Bounce`, 2 = `BounceCap`, 3 = `Moving` (amplitude `DriftAmplitudeMin..Max` 1.5 to 3.0 u, width capped at `DriftMaxWidth` 4 u so the sway has room), 4 = `Sticky`, 5 = swinging gongs (hazards, below).
Safety rules so a special never sits alone on the only path (the bot verifies the result):
- After a `Sticky` platform the next gap is at most `StickyNextGapMax` (1.8 u) and the reach uses the sticky jump multiplier.
- After a `Bounce`/`BounceCap` platform the next gap is at most `BounceNextGapMax` (4.2 u) and the edge-to-edge distance at most `BounceNextDxMax` (3 u); two bounce platforms are never adjacent (the landing speed on a pad is set by the previous flight).
- `Moving` platforms keep the base position as the reach anchor; the bot waits for a good phase.
The `share` is applied per generated row; rows from chunks, the combo ladder and the hidden-gem row are never signature platforms.

**BounceCap.** New `PlatformKind.BounceCap = 7`, launch speed = jump speed x `BounceCapMultiplier` (1.8; Bounce stays 1.4).

**Pickups (doc 08 section 7; update 2026-10-20: the coin parts of this paragraph are retired by economy v2, stars and gems remain; the draw position equals the Sim position).** `Pickup {Id, Kind, X, Y, Radius}`, collected once when the player centre (X, feet Y + `PlayerCenterY` 0.5) is within `Radius` (integer squared-distance compare). Per row: path coins on the jump arc between the previous and this spine platform (probability `PathCoinPercentEasy/Hard` 100 to 60 by d, 100 = exactly one per row), then a risky coin with probability `RiskyCoinPercentEasy/Hard` 10 to 90: either an edge side-route next to the platform or a high overshoot route above it, half of them as a pair. Multiplied by `ClassCoinPercent` (100,100,100,160,120). Result: about 70 coins on a 60-row easy level, about 115 at d = 1, about 190 on complex 60-row levels, about 350 on the 150-row L15. One rare 1-gem pickup per level with `GemChancePercent` 3 (deterministic by seed), on a risky edge spot.
In-run coins on `SimState.Coins`: landing on a new highest row +`LandingCoins` (1); +`ComboLandingCoins` (2, total, not additional) when that landing continues a combo (a qualifying multi-floor landing while `Combo > 0`); +`ExtraFloorCoins` (1) per floor gained beyond 1 (floors of the jump, capped by the new rows reached). Landing coins are off in endless. `Score` is unchanged (floors x 10 + combo^2 x 5, no coins).
`HiddenGem` pickups count in `HiddenGems`, not in `Gems`.

**Hazards: swinging gongs.** `Hazard {Id, Kind=Gong, X, Y (anchor), Radius, Period, Phase, Amplitude}`. Position at tick t: triangle wave on X over `Period` ticks, `Y` rises by `GongArcRisePercent` (25 percent) of the amplitude at the extremes (pendulum). A hit (distance <= gong radius + `PlayerHitRadius` 0.45 between centres) sets `Vx` to `GongKnockbackVx` (0.12 u/tick) away from the gong, sets `Vy` to +/- `GongKnockbackVy` (0.05 u/tick) away from it when airborne, starts `GongInvulnTicks` (90) of invulnerability and counts in `Hits`. Gongs never kill by themselves. Placement: in the jump corridor between two spine rows, offset 1 to 2.5 u from the corridor centre, amplitude `GongAmplitudeMin..Max` (1.5 to 3 u), radius `GongRadiusEasy..Hard` (0.6 to 0.9 u). Region 5: from level 3 (half density) with `GongDensityEasyPercent..Hard` (6 to 30 percent of rows) rising with d. Other regions get none.
`SurviveWave`: the middle rows (`WaveStartPercent` 35 to `WaveEndPercent` 65 of the height) get `WaveDensityPercent` (85) gongs per row (a second one 42 percent of the time) with shorter periods, on every region (also regions without the gong signature); the goal completes at the top row.

**Authored chunks (doc 08 section 4, D15).** `ChunkLibrary.All`: `chunk_complex_a..f` (class 3) and `chunk_gauntlet_a..f` (class 4), 6 to 8 rows each, relative X as permille of the screen width. Complex: widths 2.6 to 3.6, gaps 2.6 to 3.8, mixes of zigzag, stairs, pillars, bounce garden, drift, crumble. Gauntlet: widths 1.8 to 2.4, gaps 3.6 to 4.2, moving/vanishing/crumble/bounce mixes. The builder places chunks from `ChunkStartRow` (10) every `ChunkInterval` (14) rows after the previous chunk, cycling through `LevelSpec.FixedChunks`, plus one chunk ending the level. A chunk is mirrored on a seeded coin flip; its first row is moved into reach of the previous platform (same reach rule as generated rows) and later rows keep their authored offsets (clamping to the walls only shrinks offsets). Unknown chunk ids are skipped silently. Tests check every chunk against the generator reach rule.

**Goals (all in `GoalEvaluator`; update 2026-10-20: `CollectCoins` and the time part of `Speedrun` are retired, see the doc sync note above).** ReachFloor/BossChase: `Row >= Goal.Value`. CollectCoins: `Coins >= Count` (landing coins count). ComboChain: number of landings that gained at least `Value` floors in one jump (from the platform jumped from; `SimState.JumpHist`, 8 buckets, values above 8 are treated as 8) is at least `Count`; the builder inserts a **combo ladder** of `Value*Count+2` tight rungs (rung gap = `ComboLadderSpan` 3.6 u / Value; from Value 4 up the rung is `LadderMinRung` 1.0 u in two staggered columns, see Stack rule) at about 30 percent of the height, because normal gaps (>= 2 u) make a 3-floor jump impossible. NoWallBounce: `Row >= Value` with `WallBounces == 0` (a wall touch while airborne counts). FindHiddenGem: `HiddenGems > 0` (**economy contract**: the hidden gem is counted in `SimState.HiddenGems`, never in `Gems`; the goal completes when `HiddenGems >= 1`, so the economy pays the owner-decided +1 wallet gem, first clear only, when `SimState.HiddenGems >= 1` at goal completion and the level was not cleared before. The Simulation does not know about first clears or wallets); the gem floats `HiddenGemHeight` (1 u) above a 2.4 u side platform on the same row as a main platform, around the middle row, reachable by the same reach rule. Speedrun: `Row >= Value` and `Tick <= TimeSec * 60`; Speedrun levels use the **normal gaps** (owner decision 2026-10-19: the `SpeedrunGapPercent` halving was removed, the time goal was relaxed instead). Content: `timeSec` 75 on level 9 of every region (slowest bot time 61.0 s, margin 1.23; `SPEEDRUN_TIME_SEC` in `gen_content.py`). SurviveWave: top row (see above). BossChase: `Row >= Value`; with `LevelSpec.Ramp` the scroll speed uses the endless step formula (+4 percent per 25 floors) clamped to `CampaignRampCapPercent` (60 percent; reached at row 375, so never within a 150-row level: at row 150 the ramp is +24 percent). The player speed ramp stays endless-only.

**Stars (update 2026-10-20: superseded by economy v2: 3 collectible star pickups per level; the coin-target and time stars described next are history).** **Star 2 coin targets (owner decision 2026-10-19: raise the targets, keep landing coins).** Regions 1-5 read `Content/config/coin_star_targets.json` (generator `gen_content.py`, table written by `CoinStarTargetTests` with `UPDATE_COIN_TARGETS=1`): target = max(old target `20 + 5*index`, 85 percent of the bot's proven coin lower bound rounded down to a multiple of 5), capped at the bound (flag `capped`). The bound is the coins held when the run ends, i.e. at goal completion (owner decision): at the top row for most goals, earlier for collectCoins, comboChain and findHiddenGem (`LevelBot.MaxCoinsAtGoal`). Regions 6-30 (not playable in the five-region build) keep `20 + 5*index`. Capped levels (10 of 75): level 4 (collectCoins 15) in all five regions (target 15, no room above the goal count) and level 11 (comboChain 6x1) in all five regions (bound 59 to 70, below the old target 75).

`StarEvaluator.Stars` = number of satisfied entries of `spec.Stars` when the goal is complete (0 otherwise): clear, coins >= Value, noRevive (`revivesUsed == 0`, the caller passes the count), time (`ticks <= Value*60`). `Earned` returns the bit mask in `spec.Stars` order.

**Revive.** `Sim.Revive(ref s)` puts a dead player back on the highest landed platform, `ReviveInvulnTicks` (120) of invulnerability, `KillY` set `ReviveKillDistance` (10 u) below, `RevivesUsed++`. No UI, no payment.

**Determinism.** Three independent `Rng` streams from `spec.Seed` (platforms, pickups = seed ^ 0x2F1A7C35, hazards = seed ^ 0x5A3C9E17); sorting uses total orders. `LevelData.ComputeHash()` is an integer hash for golden-level tests and server checks.

## Bot (T4)

`LevelBot(sim, spec, data, maxNodes).Solve()` plays the 1-star goal. Depth-first search over landing states with real-Sim rollouts. Jump options: homing jumps to every platform of the next 3 rows (and to the combo row), with waiting, a back-off run to build speed on narrow platforms and closed-loop air steering; for bounce pads it also picks the next target so the pad is entered with speed toward it; plus scripted run/air variants. Goal-aware cuts: no wall bounce, stay near the hidden gem row and the combo ladder, time limit. Speedrun uses best-first search on elapsed ticks (row guess 45 ticks per remaining row; an upper bound of the minimum time, not a proven optimum). `MaxCoins(beamWidth)` / `MaxCoinsFrom(state, beamWidth)` / `MaxCoinsAtGoal(beamWidth)` (stops where the goal is met) is a row-layered beam search (homing jumps only) that maximises coins on a run that completes the goal and reaches the top row; it returns a lower bound of the true maximum and is used for the information-only coin-star report (the test takes the best of the solving line, a beam from the start and a beam continued from the end of the solving line). The legacy constructor `LevelBot(sim, targetRow, maxNodes)` keeps the original scripted search for platform-only levels (endless, old shipped-level test). `Tests/Simulation/SOLVABILITY_REPORT.md` is rewritten by the T4 test on every run.

Bot limits worth knowing: it never revives, never plays for style, and a level counts as solved when `GoalEvaluator.IsComplete` holds on a line that stays alive. Levels the bot cannot solve are generator bugs (fix the builder, not the budget); budget 20000 nodes, the slowest shipped level needs about 4800.

## Endless mode (T13, owner decision 2026-10-20)

`EndlessTower` (Simulation/EndlessTower.cs) is the endless world of one region: no goal, no stars, no pickups, no chunks; the run ends only when the player falls. `LevelSpec.Endless = true` marks the spec (built by `EndlessTower.MakeSpec(seed, regionOffset, signature, difficultyFloors)`, or `LevelSpecFactory.BuildEndless(region, seed, floors)` on the Unity side; `Goal` is a never-reached placeholder `ReachFloor int.MaxValue`).

- **Generation.** Rows are generated one after the other from one `Rng(seed)` (gongs: second stream seed ^ 0x5A3C9E17), same geometry and reach rules as the generated rows of `LevelBuilder` (fixed easy ladder for rows 1-4, then ladder / dense / zigzag patterns of 6-10 rows, gap cap `NormalGapMax` 4.2 u below the standing peak 4.51 u, small-platform gap cap, sticky/bounce follow-up limits). The tower is **prefix stable**: growing it never changes existing rows or ids (test `TowerIsPrefixStable...`), so a run can be rebuilt from the seed alone.
- **Difficulty.** `DifficultyAt(row) = base + offset * (1 - base)` with `base = min(1, row / EndlessDifficultyFloors)` (400, remote config `generator.endlessDifficultyFloors`): the tower starts at the region offset and reaches d = 1 at floor 400. Signature platforms (bounce flowers, bounce caps, drifting, sticky gum) appear on spine rows from row 5 with the share `SignatureBase..MaxPercent` (15 to 40) by d; region 5 gets gongs (`GongDensityEasy..Hard` 6 to 30 percent of rows by d, from row 6).
- **Scroll.** `Sim(cfg, data, spec.Difficulty, endless: true, false)`: base scroll from d = region offset applied to 0.05, the 5 s step-ups of the difficulty setting, and the floor ramp (`RampPercentAt`: +4 percent per 25 floors, cap +150; the player max speed gets half of it). Landing coins are off in endless (D3).
- **Growth in chunks.** The tower is built `ChunkRows` (40) rows at a time and kept `LookaheadRows` (60) above the player (`EnsureAhead(playerRow)`, first build 100 rows). Each growth publishes a new `LevelData` snapshot (new arrays, `Version++`); the caller builds a new `Sim` from it (`tower.CreateSim()`; Sim is stateless) and calls `Sim.GrowState(ref state)` to extend the per-platform arrays. This allocates once per chunk (about every 15 s of climbing), never per tick. Cap: `MaxRows` 7000 (Q16.16 holds about 32000 u).
- **Tests** (`Tests/Simulation/EndlessTests.cs`): determinism per seed, prefix stability, every row gap <= 4.2 u and < standing peak over 600 rows in all 5 regions, platforms sorted by Y, difficulty curve, the bot climbs 40 floors for 3 seeds x 5 regions and 150 floors in every region, growth keeps a run alive, golden hash (region 3, seed 12345, 100 rows). The campaign golden hashes (`level_hashes_r1-5.txt`) are untouched: `LevelBuilder` and `LevelGenerator` were not changed.

## Stack rule and scroll limit (owner report 2026-10-20, region 1)

**Report.** "In region 1 there were 8 to 10 platforms stacked and the moment I touched them, game over." Audit: `Tests/Simulation/Region1AuditTests.cs` (category Audit) writes `Tests/Simulation/REGION1_AUDIT.md`.

**Cause 1, the stack (builder).** The only 8-platform column in region 1 was the **combo ladder** of `lvl_001_11` (comboChain 6x1, rows 18 to 25): eight 6 u wide platforms at the same x with rungs of only 0.6 u (`ComboLadderSpan` 3.6 / 6), 6 platforms inside a 3 u window. `lvl_001_05` (3x2, rows 18 to 25) has the same ladder with 1.2 u rungs (no problem by the rule). The same ladders exist in regions 2 to 5 (levels 5 and 11). Dense patches (up to 4 platforms on one row, two rows within 3 u) reached 5 platforms per window on lvl_001_04, 06 and 15. Nothing in `Sim` kills the player on touching a platform (platforms are one-way, no underside or side collision; death is only `Y < KillY`, or revive/hazard rules), so a "game over on touching" was the scroll (cause 2) arriving while the player was inside the ladder.

**Cause 2, the speed model.** Owner steps of 20/40/60/80/100 percent per 5 s on a 120 percent base, capped at 400 percent in `GameSession`, make the screen faster than the best possible climb. Fastest bot climb (best-first line, default config) on region 1 is 6.5 to 8.2 u/s (rows skipped with run jumps); a good human sustains perhaps 60 percent of that. Scroll speed at 100 percent per 5 s on lvl_001_11 (d 0.62, base 1.72 u/s): 5.15 u/s at 10 s, 8.58 u/s from 20 s on; on lvl_001_15 12 u/s from 20 s. See the tables in `REGION1_AUDIT.md`.

**Rule (implemented in `LevelBuilder`, `LevelGenerator`, `EndlessTower`).**
- At most `MaxPerWindow` = 4 platforms (any x, any kind) in any `WindowHeight` = 3 u window. Optional platforms (dense extras, the second platform of a row, endless equivalents) are placed only while the window ending at them holds at most 2 others, which keeps a slot free for the next spine platform. The hidden gem side platform may use the third slot.
- No stack of 5 linked platforms (surfaces within 1.5 u, horizontal gap at most 1 u).
- Rows closer than 1.2 u only when horizontally separated by at least 2 u (edge to edge).
- Combo ladders: Value 3 keeps 1.2 u rungs in one 6 u wide column; Value 4 or more uses `LadderMinRung` 1.0 u rungs alternating between two columns of `LadderZigWidth` 2.8 u that are `LadderColumnGap` 2.2 u apart edge to edge (a Value-6 jump rises 6.0 u, within the full-speed peak 7.33 u); the row below the ladder is at least 3.05 u under its first rung.

**Scroll limit (SimConfig, for the owner's decision).** `ScrollStepMaxSteps` = 6: the steps stop after 30 s, so the owner's 20/40/60/80/100 percent steps stay fully visible for the first 30 s and then flatten. `ScrollMaxSpeed` = 4.0 u/s: absolute ceiling of the campaign scroll (not endless); the hardest base speed is 2.4 u/s (d = 1), the fastest bot climb on the hardest region 1 level is 6.6 u/s. The runtime percent cap (`GameSession.ScrollStepCapPercent`, now 150) still applies on top.

**Tests.** `StackRuleTests` (no stack above the limit in all 75 levels, generated towers and ladders; scroll flattening and ceiling; bot survives region 1 at the hardest step table with the game config). `GoldenLevelHashesAreStable` literals and `Content/golden/level_hashes_r1-5.txt` were regenerated (levels re-rolled only where dense extras, second platforms and combo ladders changed).

## Power-ups (docs/15 FR-PWR; reworked 2026-10-31 by owner decision)

Player-only effects; they never change a layout (golden hashes unchanged) and never read or change `GoalEvaluator`/`StarEvaluator`. Files: `PowerUps.cs` (`PowerUp` enum with stable ids 1 to 11, `PowerUps` helpers: id mapping, `InputBit`, `SatAdd`, `TotalTicks`, `ActiveTicks`, `CanActivate`), `Sim.cs` (`SimInput.PowerFirst`/`PowerMask`, the effects inside `Step`), `SimConfig.cs` (every number, section "Power-ups").

- **Input and stock.** One input bit per TYPE: Flight 8, Rocket 16, Double Jump 32, Wall Stick 64, Shield 128, Magnet 256, Slow Time 512 (`PowerUps.InputBit(type)`, `SimInput.PowerMask` = 1016). There is no loadout, no carry cap, no stock cap. The OWNED STOCK is not part of `SimState` (the bot copies the state on every recursion level): `RunSession` counts it, drops a tap whose type has no unit left and takes one unit per accepted tap. The sim itself accepts every tap of an implemented type while the player is alive. Flight and Rocket exclude each other.
- **Stacking.** A tap while the effect runs ADDS the full base time onto the remaining time (Magnet 30 s + tap = remaining + 30 s). No maximum: timers are ints and all additions saturate (`PowerUps.SatAdd`). Rocket adds another `RocketFloors` (20) rows and `RocketTicks` (240) ticks to the running burn.
- **Numbers** (ticks, 60 per second): Magnet 1800 (pickup radius +2 u); Shield 3600 (gongs cannot hurt at all: no hit, no knockback; the old fall rescue is gone); Wall Stick 1800 (hold 90, wall jump 6 u/s away, re-stick cooldown 15); Slow Time 1800 with the auto-scroll exactly 50 percent slower (applied after the scroll ceiling); Double Jump 1800: while the window runs every air phase has one extra standing-jump-strength jump (only while falling; cleared on every landing); Rocket 240 ticks per tap and 20 floors: the burn closes the gap to the target row evenly over the remaining ticks (arrives exactly on the last tick, no steering, gongs harmless, then 60 ticks of slow fall); Flight 600 at 8 u/s with normal air steering, gongs harmless, then 60 ticks of slow fall; slow fall = gravity 35 percent, fall speed at most 6 u/s.
- **Finish cannot be skipped.** `powerCapY` = the Y of the highest platform at or below `min(level.Rows, spec.TargetRow()) - PowerFlightRowsBelowTop` (3); Flight/Rocket stop there and fall slowly (a Rocket target above it is clamped). Endless has no cap.
- **Assisted landing.** The air phase of Flight/Rocket sets `Assisted`; `Land` then treats the jump as gaining 0 floors for combos, `JumpHist`, `LastJumpFloors` and landing coins (score for new rows still counts).
- **State size.** Power-up fields in `SimState` are plain ints for the timers; keep the count small (the bot recurses with copies of the state; `LevelBot.Solve` runs on a 128 MB stack thread).
- **Tests** (`Tests/Simulation/PowerUpTests.cs` and `PowerUpStackTests.cs`, category `PowerUps`): exact numbers on hand-built towers, per-region cases on level 5 of each region, chaos runs with random activations of all seven, stacking math, saturation, gongs harmless (Shield/Rocket/Flight), Slow Time exactly half, Rocket 20 floors in 4 s, Flight steering, timed Double Jump, golden hash after use, stars unchanged.

## Random layout per attempt (owner issue 2026-10-31, docs/23 Gameplay 4, CRITICAL)

Every campaign attempt (start, retry, next level, re-entering the Run scene) plays a NEW layout; difficulty, goal and star targets stay the level's.

- **Seed.** `LevelSpec.MixAttemptSeed(level.Seed, attemptSeed)` (0 keeps `level.Seed`). `LevelSpecFactory.Build(level, region, attemptSeed)` sets `Spec.Seed` and `Spec.AttemptSeed`; `GameSession.NewAttemptSeed()` draws one per attempt (`GameSession.FixedAttemptSeed` pins it for QA); `RunSession.AttemptSeed` / `LayoutInfo` ("lvl_001_01 attempt A layoutSeed S", also logged by `RunController.StartRun`) reproduce a run. A revive keeps the session and layout. Rewards still use `level.Seed` (milestone gems), so payouts do not depend on the attempt.
- **Base layout.** `AttemptSeed == 0` runs the original builder bit for bit (golden hashes, audits and the Unity EditMode tests use it).
- **Balanced mode** (`AttemptSeed != 0`, `LevelBuilder`): the level's ranges are unchanged (gap, width, offset ranges of d), so gaps, x positions, widths, pickups and gong parameters are new draws of the same distributions. What used to be independent coin flips is made exact so no attempt is luckier than another: the signature platforms take exactly round(share * free rows) rows (bounce kinds: share / (1 + share), the effective mix of the never-chained rule; no bounce next to a bounce or chunk), the layout patterns (ladder / dense / zigzag) come from a shuffled bag, and hazard rows per density zone are exactly round(chance * rows) (at least one). Combo ladders, authored chunks, the hidden gem row and the wave zone stay where the level puts them.
- **Safety net.** `DropTouchingExtras` removes an optional extra platform that the walls pinned against its row mate (gap under 0.05 u); the spine platform and the gem side platform are never removed. Reachability is by construction (the same reach limits as the base builder) and proven per seed by `RandomLayoutTests` (bot on 75 levels x 20 seeds).
- **Tests.** `RandomLayoutTests` (category `RandomLayout`).

## Region 1 special platforms, difficulty ramp, endless (doc 24, owner issue list 26, 2026-10-31)

**Seven new `PlatformKind`s** (values 8 to 14, existing values unchanged; `Platform.Dir` is new: -1/+1 or 0; all numbers in `SimConfig`, section "Region 1 special platforms"). Each is deterministic fixed-point and none can end a run by itself (the only death is still the kill line).
- **WindPetal (8):** while grounded on it a gust moves the player `WindPush` 2.5 u/s; direction flips every `WindFlipTicks` 150 (`Platform.Dir` = first direction, `Phase` 0..299 offsets the clock). `Sim.WindDirection(id, tick)`, `Sim.WindFlipCue(id, tick)` (last `WindCueTicks` 30 before a flip, the view flips and blinks the arrows then).
- **HiveLift (9):** surface bobs +-`HiveBobAmplitude` 1.2 u (2.4 u peak to peak = 0.8 of a 3 u row), period `HivePeriodTicks` 180 (triangle wave, `Phase`). `Sim.PlatformY(id, tick)`; the grounded player rides it; the landing search is widened by the bob (`bobMargin`, zero without hives). Gaps to and from a hive are kept in [`HiveGapMin` 2.6, `NormalGapMax` - amplitude = 3.0] by the builder.
- **SnapDaisy (10, hazard type):** closes `SnapCloseTicks` 90 after the landing, shut `SnapReopenTicks` 120, then open (a landing after the reopen starts a new countdown). State: landing tick in `SimState.CrumbleTick[id]`; `Sim.SnapPhase` (0 open, 1 counting, 2 shut), `Sim.SnapCountdown` (3, 2, 1), `IsSolid`.
- **Dandelion (11, launcher):** on landing `Vy = JumpSpeed * DandelionLaunch` (1.14, jump height x1.3) and `Vx = Dir * DandelionVx` (about 4 u sideways over the flight). The next row sits where the arrow points (`SpecialPlatforms.DandelionNextX`, 2.2 to 3.8 u).
- **ThornBush (12, hazard type):** the half on side `Dir` (beyond `ThornDeadZone` 0.15 u from the centre) is thorny. A landing or a step onto it hops the player away (`ThornKnockVx/Vy`), counts no landing, no hit, only `SimState.ThornKnocks`. Never kills. Width at least 4 u.
- **Ladybug (13):** short horizontal path (`Amplitude` 0.8 to 1.4, `Period`, `Phase`) like Moving; while the player stands on it the path clock runs 1.5x (`LadybugBoostPercent`): the extra clock ticks accumulate in `CrumbleTick[id]`. Use `Sim.PlatformX(id, tick, crumbleTick)` / `PlatformXAt(state, id)` for the true position (`PlatformX(id, tick)` is the unboosted path).
- **Seesaw (14):** on landing `SimState.TiltDir` = side landed on (centre strip `SeesawDeadZone` 0.2 uses the travel direction); while grounded it slides the player `SeesawSlide` 1.8 u/s that way. `Sim.SeesawTilt(state, id)`.
- New `SimState` fields: `LandTick`, `TiltDir`, `ThornKnocks`. `LevelData.ComputeHash` includes `Platform.Dir` only when non-zero (older hashes are untouched).

**Placement (`SpecialPlatforms.cs`, `RegionPlatformSets` in `LevelSpec.cs`).** `LevelSpec.NewPlatforms` (null = the set of the signature; region 1 = `BounceFlowers` = the seven) is the data-driven switch: regions 2 to 5 add their kinds to `RegionPlatformSets.For`. The flower is the eighth option of a row. Level 1: none. Level 2: `Level2SafeSpecials` 2 + `Level2HazardSpecials` 1, no launcher or flower. Levels 3 to 15: `SpecialShareLevel3Percent` 15 rising linearly to `SpecialShareLevel15Percent` 55 of the FREE generated rows (rows of combo ladders, chunks and the gem row are not free, so chunk levels 5/10/15 and the big ladder of 11 carry a smaller share of all rows). The number of special rows is exact per level and identical for every attempt seed (`SpecialPlatforms.Plan`, own Rng stream `seed ^ 0x1B873593`, base layout and balanced layouts alike); only places and kinds vary. Rules: hazard types (Thorn, Snap) get at most their share of the options (a quarter in region 1), never in adjacent rows, never right after a launcher, at least 6 rows apart up to level 6 (`HazardEarlyRowsPerHazard`, owner decision); no launcher after a launcher; the last 3 rows and gem row +-2 take neither launchers nor hazards; rows beside a ladder or chunk take no hive or launcher. Widths: wind >= 3, thorn >= 4, seesaw 3 to 6, ladybug/dandelion/hive 2 to 4, snap >= 2.

**Difficulty ramp (all regions).** `LevelSpec.EffectiveDifficulty(cfg)`: levels 1 and 2 and endless keep `Difficulty`; from level 3 it never falls below a floor rising linearly from `RampFloorLevel3Permille` 300 (level 3) to 1000 (level 15). The builder (gap, width, offset, signature share, gong density) and the scroll speed (`Sim(cfg, level, spec)`) both use it, so every level from 3 on is clearly harder than the one before in every region. `DifficultyReportTests` writes `Tests/Simulation/DIFFICULTY_REPORT.md`.

**Endless.** Same kinds through `RegionPlatformSets` (`EndlessTower`, own Rng stream `seed ^ 0x6A09E667`, prefix stable): the special share rises from 15 percent to 55 percent over `EndlessSpecialRampFloors` 150 floors, same adjacency rules (hazard spacing 6 rows up to the level-6 equivalent, i.e. the first ~40 floors). `RunController.StartEndlessRun` already draws a new seed (`GameSession.NewEndlessSeed`) for every run.

**Bot.** `LevelBot.Solve` runs on a 128 MB stack thread (SimState grew); launchers include the dandelion; snap daisies allow only short waits; time-dependent kinds are keyed by the clock; `MeasureOptions` is the difficulty probe used by `DifficultyReportTests`. Proofs: `Region1PlatformTests` (region 1 levels 2 to 15 x 24 seeds), `RandomLayoutTests` (all 75 levels x 20 seeds).

**Gems.** `SimConfig.DifficultyGemPermille` {22, 22, 25, 27, 29} (was {32, 32, 35, 38, 41}, x0.7 rounded): about 55 to 75 placed gem value per region.
